# Формат листів: персонаж і корабель

Цей файл відповідає на два питання: **що лежить у файлі листа** і **чого там не буде
ніколи**. Він для людини, не для програміста: якщо ти колись захочеш відкрити лист
текстовим редактором і щось виправити — читай звідси.

Листи лежать у двох теках:

| Тека | Що там |
| --- | --- |
| `state/characters/source-exports/` | пʼять персонажів партії, як їх віддав sw5e.com |
| `state/characters/companions/` | компаньйони (дроїд Нигри) — формат наш, бо на sw5e.com їх немає |
| `state/ships/` | кораблі. Поки один: `mandrivna-zorya.json` |

---

## Головне правило обох форматів

**У файлі — лише вибори людини. Усе, що можна порахувати, не зберігається** (ADR 0003).

Максимум ХП, КБ, сейви, DC сил і технік, бонуси атак, список маневрів класу, корпус і
щити корабля, його швидкість, трюм, мінімальний екіпаж, вартість — нічого з цього в
файлах немає. Рушій рахує це щоразу при старті сервера.

Це не естетика. З цього правила випливають три речі, заради яких усе й робилось:

1. **Оновлення застосунку не може нікому зіпсувати персонажа.** Міняється код, а не дані.
2. **Виправив характеристику — усе решта перерахувалось саме.** Підняв Інтелект корабля
   на 2 — мінімальний екіпаж зменшився сам, бо він рахується з Інтелекту.
3. **Лист не може тихо розійтися з книгою.** Числа беруться з `vendor/`, а не з того,
   що колись хтось вписав.

Зворотний бік: **кидок — це вибір людини, і він зберігається.** У листі персонажа
лежать саме кидки ХП за рівні, а не сума; сума — обчислюване.

## Лист персонажа

**Формат — рідний експорт sw5e.com** (ADR 0001). Ми не перейменовуємо полів, не
«причісуємо» їх і нічого свого туди не кладемо — крім namespace `holotable` у самому
кінці. Причина проста: доки формат той самий, лист можна завантажити назад на sw5e.com,
підняти там рівень і знову експортувати. Це наш страховий поліс.

Як оновити персонажа: **завантажити файл зі sw5e.com** (кнопка експорту, не копіювання
тексту — див. нижче) і покласти в `state/characters/source-exports/` під тим самим
імʼям. Усе інше зробить рушій.

Що в ньому лежить, коротко:

| Поле | Що це |
| --- | --- |
| `name`, `species`, `background` | імʼя, вид, передісторія |
| `classes[]` | класи й рівні, **кидки ХП** за рівні, приріст характеристик, архетип |
| `baseAbilityScores` | шість характеристик до приростів: `{"Strength": 9, …}` |
| `equipment[]` | речі: назва, кількість, чи вдягнене |
| `currentStats` | **стан сесії**: втрачені ХП, тимчасові ХП, витрачені поінти сили й техніки, кубики здоровʼя, рятівні від смерті, натхнення, умови, виснаження |
| `tweaks` | **ручні правки** власника на sw5e.com: `bonus` додається, `override` замінює |
| `customFeatures`, `customEquipment`, `customForcePowers`… | те, що власник дописав руками |

Повний перелік типів — `packages/schema/src/rawCharacter.ts`, він виведений із пʼятьох
справжніх листів, а не з документації.

**Пастки цього формату** — `docs/ПАСТКИ-ДАНИХ.md`, тринадцять штук. Найважливіші дві:
приріст характеристик за вид у листі **не зберігається** (він у компендіумі), і лапки
« » замість `"` означають, що лист скопіювали текстом замість завантажити файлом.

## Лист корабля

На sw5e.com кораблів немає взагалі, тому формат наш. Але зроблений він **навмисне схожим
на лист персонажа**: ті самі назви полів (`baseAbilityScores`, `currentStats`,
`equipment`), ті самі правила, та сама звичка зберігати вибір, а не результат. Хто
прочитав один лист — прочитає й другий.

Типи й перевірка — `packages/schema/src/rawShip.ts`.

### Що зберігається

| Поле | Що це | Приклад із «Мандрівної Зорі» |
| --- | --- | --- |
| `name`, `slug` | назва й іменник для посилань | `Мандрівна Зоря`, `mandrivna-zorya` |
| `model`, `manufacturer` | модель і верф, якщо відомі | `YT-1300f`, `Верфі Кариди` |
| `size` | розмір категорії | `Medium` |
| `tier` | тір від 0 до 5 | `0` |
| `role` | роль тіра 0 зі списку свого розміру | `Freighter` |
| `baseAbilityScores` | шість характеристик **до** приросту за роль і тіри | Статура `13`, не `14` |
| `abilityScoreImprovements[]` | що саме підняли на кожному тірі | поки порожньо |
| `savingThrowProficiencies` | два сейви, вибрані при побудові | `Strength`, `Dexterity` |
| `skillProficiencies`, `skillExpertise` | володіння навичками корабля | `Astrogation` |
| `equipment[]` | броня, щити, реактор, муфта, гіпердрайв, зброя — **лише назви з книги** | `Quick-Charge shield` |
| `modifications[]` | модифікації з кількістю | `Storage Compartment` ×2 |
| `crew[]` | хто за якою посадою і з яким рангом | Алістер — `Gunner` |
| `currentStats` | **стан сесії**: втрачений корпус і щити, витрачене паливо, кубики корпусу, кубики сили, умови | усе по нулях |
| `notes` | нотатки власника | — |
| `holotable` | наш namespace: версія формату, звідки дані, коли звіряли | — |

### Чого в ньому немає і не буде

Корпус, щити, регенерація, КБ, зменшення шкоди, швидкість, поворот, сейви, навички,
атака й DC зброї, місткість трюму, паливо, слоти модифікацій, максимум сюїт, мінімальний
екіпаж, кубик сили, вартість. Якщо таке поле зʼявиться у файлі — перевірка листа
(`checkRawShip`) скаже про це вголос.

Ось звідки кожне з них береться:

| Число | Звідки рахується |
| --- | --- |
| Корпус | кубики розміру: максимум першого + середнє решти + Статура за кожен кубик |
| Щити | те саме, але від Сили, далі множник типу щита (Quick-Charge — ⅔) |
| Регенерація щитів | максимум кубика щита × коефіцієнт типу щита (Quick-Charge — 3/2) |
| КБ | 10 + Спритність (броня може обмежити) + бонус за тір |
| Зменшення шкоди | з броні |
| Швидкість і поворот | з ролі тіра 0 для свого розміру |
| Сейви корабля | модифікатор корабля + бонус майстерності того, хто за станцією (якщо корабель має володіння цим сейвом, а в людини є ранг у посаді) |
| Атака зброї й DC | Мудрість корабля + бонус майстерності того, хто стріляє (з рангом) |
| Шкода зброї | кубики зброї + Сила корабля |
| Трюм | базова місткість розміру × (1 + кількість `Storage Compartment`) |
| Паливо | з розміру |
| Слоти модифікацій | з розміру, плюс те, що додають модифікації (Equipment Room дає +4) |
| Максимум сюїт | за розміром і Статурою (Medium: 3 + Статура) |
| Місткість сюїти (скількох селить) | з розміру (Medium: 4) |
| Мінімальний екіпаж | з розміру й Інтелекту корабля |
| Кубик сили | з тіра |

Через останній рядок таблиці сейвів і атак немає на листі **принципово**: вони залежать
від того, хто саме зараз сидить за станцією, а це міняється посеред бою.

### Як додати ще один корабель

1. Поклади файл `state/ships/<slug>.json`, узявши «Мандрівну Зорю» за взірець.
2. Назви спорядження й модифікацій пиши **точно так, як у книзі** — тест
   `tests/f075-ship-sheet.test.ts` звіряє кожну назву з компендіумом і падає
   українською, якщо назви немає. Підглянути правильне написання можна в довіднику
   застосунку.
3. Запусти `ПЕРЕВІРИТИ.bat`. Він скаже і про зламаний JSON, і про вигадану назву, і про
   обчислюване число, якому не місце у файлі.
