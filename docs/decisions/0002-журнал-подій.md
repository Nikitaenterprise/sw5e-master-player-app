# 0002 · Журнал подій — єдине джерело правди

**Рішення.** Кожна зміна стану — подія, що дописується в кінець
`state/events/session-NN.jsonl` і розсилається всім підключеним. Стан у пам'яті —
результат проходу по журналу. Рядки журналу ніколи не переписуються й не видаляються.

```
{ "id":"01JC8X…", "at":1763240000000,
  "actor":{"kind":"player","id":"anton","character":"krinzh-dor"},
  "type":"currentStats.patch",
  "patch":{"hitPointsLost":{"from":4,"to":11}},
  "note":"від бластера пірата" }
```

**Чому.** Власник попросив бачити сповіщення про зміни, які внесли гравці. Журнал дає
це безкоштовно — потік змін на екрані майстра є просто рендером журналу. І ще чотири
речі тією самою ціною: відкат (бо в події є `from` і `to`), історія сесії, стійкість
до раптового вимкнення живлення (дозапис + `fsync` атомарний, втрата — максимум одна
подія), і сама синхронізація, яка зводиться до розсилання події.

**Розглядали й відкинули.** CRDT — надлишок: сервер один і авторитетний, конфліктів
не буває. Зберігання тільки поточного стану — тоді сповіщення, відкат та історію
довелося б будувати окремо, трьома різними механізмами.

**Ціна.** Журнал росте. Якщо колись заважатиме — згортання старих сесій у знімок,
але не раніше, ніж це стане справжньою проблемою.
