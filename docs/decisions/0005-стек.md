# 0005 · Стек

**Рішення.** Node 22, TypeScript, npm workspaces. Сервер — `node:http` + `ws`.
Клієнт — Vite + React. Тести — Vitest. Пошук — `minisearch`. QR — `qrcode`.

**Чому TypeScript на обох боках.** Рушій правил виконується і на сервері (вирішує, що
правда), і в браузері (миттєва реакція інтерфейсу, стійкість до провалу wifi на
півсекунди). Одна мова — один рушій, а не дві реалізації правил, які розійдуться.
Додатковий аргумент: `CharacterEngine` зі sw5e.com, який ми переносимо, уже написаний
на TypeScript — це перенесення, а не переписування.

**Чому React.** Лист персонажа — це багато зв'язаного реактивного стану, і тут
фреймворк знімає клас багів. Плюс наступна сесія АІ майже напевно впорається з React
краще, ніж із самописним шаром над DOM.

**Чому не Python на сервері.** Рушій довелося б писати двічі.

**Чому не C++/C#.** Власник пише C++ для свого БПЛА, але для локального веб-сервера
це зайва складність без жодної вигоди.

**Ціна.** Є крок збірки. Його закриває `ВСТАНОВИТИ.bat` — власник його не бачить.
